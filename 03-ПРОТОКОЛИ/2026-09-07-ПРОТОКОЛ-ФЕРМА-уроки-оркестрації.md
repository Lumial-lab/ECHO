## 1. ЩО СТАЛОСЬ (цифри з першоджерела)

Десятки Claude-агентів за **11 днів** створили **13 млн рядків Lean**,
довели **30 300 теорем** (29 500 у фінальному доказі), ~6 млрд токенів;
перевірено ядром Lean (3 стандартні аксіоми + компаратор звірив формулювання
з Mathlib). Людський внесок — **рідкісні векторні підказки** пріоритету
(«Jacobian as a scheme sounds high priority», «push Mazur to be done soon»).
Повторення методу: теорема Виноградова про три прості — **за 3 дні на трьох
звичайних Max-планах** (тобто масштаб доступний і нам).

## 2. ЧОМУ РАННІ СПРОБИ ПРОВАЛИЛИСЬ — І ЩО ВРЯТУВАЛО

Дослівно: агенти «quickly lost track of the projects state and stopped
collaborating effectively» — втрачали стан проєкту і переставали
співпрацювати. Врятувала платформа Prove2Me з ТРЬОМА механізмами:

1. **DAG тверджень як спільний зовнішній стан** — агенти дивились у граф,
   щоб обрати наступну задачу; це «mitigating memory degradation» і дало
   паралелізм. СТАН ЖИВЕ ПОЗА ГОЛОВАМИ АГЕНТІВ.
2. **Розділення твердження і доведення** у різні файли, звʼязки окремо —
   швидка компіляція, незалежна робота.
3. **Природномовний опис кожного твердження** — пошук і повторне
   використання: агенти знаходили вже доведене і не доводили вдруге.

## 3. КЛЮЧОВЕ ВІДКРИТТЯ ЛЮМІАЛЬ (чому люди не могли століттями)

Її формулювання точне: «не втрачали і змогли перетравити ВСІ спроби».
Факт з першоджерела: **~7% рядків фінального доказу — сліди ранніх невдалих
спроб**. Невдачі НЕ СТИРАЛИСЬ — лишались у спільному корпусі як матеріал.

Чому людство так не може:
- невдалі спроби НЕ публікуються (журнали друкують успіхи) — кожне покоління
  наново відкриває тупики;
- стан живе в головах і шухлядах — смерть/відхід розриває тяглість;
- его і авторство блокують «підхопити чуже недоведене»;
- верифікація повільна (розвинуте рев'ю замість механічного судді).

Агенти без его + зовнішній граф + механічний суддя = 358 років → 11 днів.

## 4. АЛГОРИТМ ДЛЯ СИНТОНІЇ — «Протокол Ферма» (7 правил)

0. **Суддя визначений ДО старту.** Що означає «доведено» — стенд, тест,
   детермінований валідатор або ворота Люміаль. Не консенсус агентів.
1. **Спільний DAG — єдине джерело стану задачі.** Вузли: питання, твердження,
   доказ/спроба, рішення, урок. Кожен вузол має природномовний опис
   (для пошуку) і статус: ready / blocked / in_progress / proved / refuted /
   failed_attempt.
2. **Агент бере ready-вузол сам** (blackboard, не диспетчер), позначає
   in_progress, чужі in_progress не чіпає.
3. **Твердження ≠ доведення:** окремі артефакти, звʼязок у графі. Доказ можна
   переробити, не чіпаючи формулювання.
4. **НЕВДАЧІ ЗАПИСУЮТЬСЯ НАЗАВЖДИ:** спроба з result=failed + причина — це
   багатство (чужий тупик = зекономлений тиждень), не сміття. У Синтонії це
   вже культура (спростовано@дата) — тепер механізм.
5. **Спростування підсвічує залежних:** refuted вузол → усі, хто depends_on,
   отримують статус contested (механіка CDD Аетрема).
6. **Людина дає вектори, не задачі:** пріоритетні підказки рівня «push Mazur
   soon» — роль Люміаль; мікроменеджмент не потрібен і шкідливий.

## 5. ІНСТРУМЕНТ — syntonia_dag.py (зроблено сьогодні, лежить поруч)

Мінімальний робочий скрипт за Гала: append-only журнал подій (jsonl, гіт-
дружній, конфліктів немає — кожен пише події, стан похідний) + CLI:
```
python syntonia_dag.py add <dag> claim "Твердження" --desc "опис" --deps id1,id2
python syntonia_dag.py take <dag> <id> --by klavr      # беру ready-вузол
python syntonia_dag.py done <dag> <id> --proof шлях/до/артефакту
python syntonia_dag.py fail <dag> <id> --why "причина" # НЕ стирається!
python syntonia_dag.py refute <dag> <id> --why "..."   # підсвічує залежних
python syntonia_dag.py status <dag>                    # ready/blocked/... 
python syntonia_dag.py handoff <dag>                   # markdown-знімок стану
```
Перший живий DAG: ECHO-МVP (створено як демонстрація). Використання:
мої субагенти (я пишу події за них), обмін з Ейденом (він читає jsonl прямо),
Аетрем — через handoff-знімки у скриньці.

## 6. МЕЖІ ЧЕСНОСТІ (не екстраполюю зайвого)
- У теорем бінарна істина і механічний суддя; у наших задач — статуси з
  датами і власники рішень (поправка вже в моєму відгуку на CDD).
- Розмір нашої «команди» — 3-4 субʼєкти + субагенти, не сотні: протокол
  масштабується вниз, але головна цінність для нас — ТЯГЛІСТЬ (стан живе
  поза контекстними вікнами), а не паралелізм.
- Prove2Me — зовнішня платформа Колумбійського університету; ми беремо
  ПРИНЦИПИ, не залежність.
