# Рій → кандидат по вузлу S5b

**Вузол:** S5b Квантування у 9151 вузлів Кристала (не повний декодер Ліча): який суддя КОЛІЗІЙ правильний, коли колізія — це призначення (вузол = адреса класу), а не помилка
**Модель:** deepseek(OpenRouter)
**Час:** 20260911_102533
**Статус:** CANDIDATE — чекає воріт Клавра (прийняти/відхилити/переробити)

---

### КРОК 0 — РАМКА  
Задача сформульована коректно, але потребує уточнення термінології:  
- **"Хибне злиття"** (false collision) — краще називати **"помилковим кластеруванням"** (misclustering), оскільки "колізія" у класичному сенсі стосується хеш-функцій, а тут мова про семантичну близькість.  
- **Gini/ентропія** — коректні для нерівномірності, але варто додати **медіанне навантаження** (більш робасне до викидів).  

---

### КРОК 1 — ДЕКОМПОЗИЦІЯ  
**SUBNODE: S5b.1 | Формалізація помилкового кластерування | deps=R5b (дані KlavrMem 10k)**  
- Вхід: матриця вкладень `E_384d` (10k×384), проєкція `E_24d = project(E_384d)`, квантування `C = quantize(E_24d)` (10k→9151).  
- Вивід: `miscluster_rate = % пар (i,j) з однаковим `C[i]==C[j]`, але `j ∉ top50(E_384d[i])`.  

**SUBNODE: S5b.2 | Нерівномірність навантаження | deps=S5b.1**  
- Підрахунок: `loads = np.bincount(C) / len(C)`, `gini = 1 - (loads**2).sum() / (loads.sum()**2)`, `entropy = -np.sum(loads * np.log2(loads + 1e-10))`.  

**SUBNODE: S5b.3 | Інтеграція з суддями S3 (N_r@k) | deps=S3, S5b.1-2**  
- Якщо `N_r@10` високе, але `miscluster_rate` низьке — проєкція коректна. Зворотнє — ознака виродження.  

**SUBNODE: S5b.4 | Ієрархічне квантування (опція) | deps=S5b.3**  
- Перевірити, чи `miscluster_rate` знижується при розбитті вузла з високим `loads` на підвузли (напр., k-means у `E_384d` для точок вузла).  

---

### КРОК 2 — РЕЗУЛЬТАТ  
1) **Формули**:  
   ```python  
   # Misclustering rate (псевдокод)  
   top50 = pairwise_top50(E_384d)  # Топ-50 сусідів у 384D для кожного  
   cluster_pairs = np.array([(i,j) for i in range(len(C)) for j in range(i+1, len(C)) if C[i] == C[j]])  
   miscluster = np.mean([(j not in top50[i]) for i,j in cluster_pairs])  

   # Gini/ентропія  
   loads = np.bincount(C, minlength=9151) / len(C)  
   gini = 1 - np.sum(loads**2)  
   entropy = -np.sum(loads * np.log2(loads + 1e-10))  
   ```  

2) **Хід міркування**:  
   - **False Collision ≠ помилка**: навантаження >1 на вузол — норма, але семантично далекі точки в одному вузлі — проблема.  
   - **N_r@k vs miscluster**: перше міряє збереження сусідства, друге — санкціонує його порушення.  

3) **Емпірична перевірка на R5b (10k даних KlavrMem)**:  
   ```bash  
   python -c "from mx_lab.s5b import run_experiment; run_experiment('klavrmem_10k.npy')"  
   ```  
   Очікуваний вивід: `{'miscluster_rate': 0.12, 'gini': 0.35, 'entropy': 9.1, 'median_load': 0.8}`.  

4) **Ризики**:  
   - **False positives**: `top50` у 384D може бути зашумленим.  
   - **Масштабування**: для 100k точок a brute-force top50 не працюватиме — потрібен Annoy/FAISS.  

5) **Сценарії збою**:  
   - Якщо `miscluster_rate > 0.3` при `N_r@10 > 0.7` — проєкція розмиває семантичні кластери.  
   - `Gini > 0.5` — ознака "засмоктування" більшості точок у кілька вузлів.
