### КРОК 0 — РАМКА (Frame Shift)  
Рамка вузла K2 коректна, але варто підкреслити, що SKU-паспорт — це не просто довільний набір полів, а **інтерфейс між стадіями конвеєра**. Акцент має бути на тому, які поля критичні для передачі товара між командами/алгоритмами, а не на "ідеальній" структурі даних.  

---
### КРОК 1 — ДЕКОМПОЗИЦІЯ  
Розбиваю K2 на під-вузли:  
1. **SUBNODE: Критерії мінімалізму полів** | Довести, що кожне поле виправдане конкретним споживачем у конвеєрі | deps=архітектура конвеєра  
2. **SUBNODE: Джерела даних для полів** | Визначити, хто (людина/система) і на якій стадії заповнює кожне поле | deps=B1 (scout-звіти)  
3. **SUBNODE: Обробка відсутніх даних** | Правила для "невідомо" (напр., `nil`, `NOT_MEASURED`, `TBD`) і як вони впливають на подальші стадії | deps=B1.5 (колонка NOT_MEASURED)  
4. **SUBNODE: Валідація на живих даних** | Протестувати схему на реальній гіпотезі SKU з artifacts/B1.4 | deps=наявність артефактів

### КРОК 2 — РЕЗУЛЬТАТ  
**1) Відповідь по суті:**  
Мінімальний SKU-паспорт для конвеєра Синтонії:  
```json
{
  "sku_id": "UNIQUE_ID_AUTO",  // генерація при створенні, споживач — будь-яка стадія логування  
  "parent_line": "creature-stickers",  // зі scout-звіту (B1), споживач — фільтрація гілок  
  "concept": "Sticker Pack: Quantum Cats",  // людина на основі артефактів B1.4, споживач — маркетинг  
  "core_use_case": "familiar for devs",  // з B1/scout, споживач — упаковка  
  "production_type": "printable-PDF",  // обрано з B1.6, споживач — фабрикація  
  "not_measured": ["unit_cost", "break_even_qty"],  // спадкування з B1.5  
  "next_stage": "design"  // замовчування: "scout", якщо звіт неповний  
}
```  

**2) Хід міркування:**  
- Поля обрані за принципом "якщо це прибрати — наступна стадія зламається". Наприклад, без `parent_line` неможливо класифікувати SKU, а без `production_type` фабрикація не стартує.  
- Поле `not_measured` — це явний стан, який відрізняється від порожнього значення (напр., `""`).  

**3) Емпірична перевірка:**  
- Запустити валідацію на даних з `artifacts/B1.4_20260916_035156.md`:  
  ```bash  
  cat artifacts/B1.4_20260916_035156.md | jq '{parent_line, concept}'  # перевірити наявність даних для обов’язкових полів  
  ```  

**4) Ризики:**  
- Якщо стадія "design" потребує додаткових полів (напр., кольорова палітра), схема зламається.  
- Поле `core_use_case` може бути суб’єктивним (напр., scout і маркетинг трактують його по-різному).  

**5) Сценарії збою:**  
- Відсутність `parent_line` → SKU "висить" в черзі без призначення до лінії.  
- `production_type: nil` → фабрикація відмовляє в обробці до уточнення.
