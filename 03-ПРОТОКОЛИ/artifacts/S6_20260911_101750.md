### КРОК 1 — ДЕКОМПОЗИЦІЯ  
**SUBNODE: S6.1 | Метрики дрейфу для PCA/NCA | deps=S2, S3**  
- Які статистики збирати: пояснена варіація (PCA: `explained_variance_ratio_` на нових точках), N_r@10 свіжих vs старих точок, відстань між центроїдами старих і нових даних.  
- Емпіричні пороги: PCA — перетренувати, якщо додана варіація >10% від початкової; NCA — якщо N_r@10 падає на 15%+.  

**SUBNODE: S6.2 | Інкрементальні стратегії | deps=S4**  
- **PCA**: використовувати `sklearn.decomposition.IncrementalPCA` з частковим оновленням базису (копіює 80% власних векторів, оновлює 20%).  
- **NCA/SupCon**: фіксувати backbone (ResNet), оновлювати лише останній шар (LR ~1e-5) на міні-батчах нових точок.  

**SUBNODE: S6.3 | Мапа переходу адрес | deps=R5**  
- При повному перетренуванні: зберігати 20% старих якірних точок, проектувати їх у стару і нову систему, будувати лінійне відображення (SVD).  
- Умова активації: якщо середня відстань між старими точками в новій проєкції >0.5 (нормована шкала Leech).  

**SUBNODE: S6.4 | CPU-стенд для перевірки | deps=S4**  
- Скрипт `drift_detector.py` з:  
  - Генерацією синтетичного дрейфу (додавання гаусових кластерів до початкових даних).  
  - Виміром часу оновлення (`time.process_time()` для IncrementalPCA vs повного PCA на 10k-100k точках).  

### КРОК 2 — РЕЗУЛЬТАТ  
1) **Правила порогів**:  
   - **PCA**: перетренувати повністю, якщо `sum(explained_variance_ratio_[:3])` (топ-3 компоненти) зміниться на >10% або N_r@10 падає на 15%. Інакше — інкрементальне оновлення.  
   - **NCA**: повне перетренування при падінні N_r@10 на 20%+ (через нелінійність).  

2) **Хід міркування**:  
   - PCA дозволяє дешеві інкрементні оновлення, але контрастивні методи вимагають повного перетренування через їхню чутливість до розподілу.  
   - Стабільність адрес забезпечується мапою переходу на основі SVD (мінімальні зсуви).  

3) **Емпірична перевірка**:  
   ```python  
   # Для PCA:  
   from sklearn.decomposition import PCA, IncrementalPCA  
   new_data = load_new_embeddings()  # shape=(n_new, 384)  
   pca = PCA(n_components=24).fit(old_data)  
   expl_var_old = pca.explained_variance_ratio_.sum()  
   expl_var_new = pca.transform(new_data).var(axis=0).sum() / new_data.var(axis=0).sum()  
   if abs(expl_var_new - expl_var_old) > 0.1:  
       retrain_pca_full()  
   ```  

4) **Ризики**:  
   - Інкрементальний PCA може «застрявати» в локальних мінімумах при різкому дрейфі.  
   - NCA-моделі вимагають GPU для часткового оновлення.  

5) **Сценарії збою**:  
   - **Overfitting нових точок**: якщо інкрементальне оновлення NCA проводиться на малому обсязі нових даних (<1k точок), якість проєкції на старих точках може впасти. Рішення: buffer з 5k точок перед оновленням.
