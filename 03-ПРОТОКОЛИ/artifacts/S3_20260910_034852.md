### КРОК 0 — РАМКА (Frame Shift)  
Задача сформульована коректно: потрібно визначити метрики для оцінки якості проєкції 384D→24D з подальшим квантуванням у ґратку Leech (E8).  
**Уточнення:**  
- «Neighborhood recall» (N_r@k) і «collision rate» — стандартні метрики для оцінки збереження сусідств при стисненні, але варто додати **відстаневе спотворення** (наприклад, MSE між pairwise distances до/після проєкції).  
- Потрібно явно вказати **референсний набір даних** (наприклад, Glove-384D або синтетичні дані з контрольованим розподілом).

### КРОК 1 — ДЕКОМПОЗИЦІЯ  
**SUBNODE: N_r@k | Формула + критичний поріг | deps=вхідні дані, FAISS**  
- Визначити, як обчислювати recall для k найближчих сусідів у вихідному та стиснутому просторі.  
- Пропозиція порогу: N_r@k ≥ 0.85 для k=10 (аналогії з ANN-бенчмарками).  

**SUBNODE: Collision Rate | Виміряти кількість унікальних конфліктів після квантування | deps=Leech quantizer**  
- Формула: `1 - (унікальні_квантовані_вектори / загальна_кількість_векторів)`.  
- Припустимий рівень: < 5% для даних з Gaussian-розподілом.  

**SUBNODE: Distance Corruption | MSE між матрицями відстаней | deps=numpy, pairwise_distances**  
- Обчислити MSE між матрицями відстаней оригінальних і квантованих векторів.  

**SUBNODE: Референсна реалізація | Код на Python (numpy+faiss) | deps=всі вище**  
- Інтегрувати метрики в єдиний скрипт з виведенням звіту.

### КРОК 2 — РЕЗУЛЬТАТ  
#### 1) Відповідь:  
Метрики для судження якості проєкції:  
- **Neighborhood Recall (N_r@k)**: частка спільних k-NN до/після стиснення.  
- **Collision Rate**: % колізій після квантування в Leech.  
- **Distance MSE**: середньоквадратичне спотворення pairwise distances.  

#### 2) Хід міркування:  
- N_r@k — золотий стандарт для оцінки збереження сусідств.  
- Collision Rate критичний для уникнення вироджених відображень.  
- Distance MSE дає глобальну оцінку спотворень.
