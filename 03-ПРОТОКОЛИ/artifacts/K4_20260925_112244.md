**Час:** 20260925_112244

**КРОК 2 — РЕЗУЛЬТАТ (K4):**  

1. **Відповідь:**  
   Правила лістингу для Notion-шаболону на основі K2 (SKU-паспорт) і K3 (виробничий пакет):  
   - **Title:** `"{title} — Notion Template"`, де `title` береться з SKU-паспорта (K2). Напр.: `"Decision Journal — Notion Template"`.  
   - **Tags:** Копіюються з `tags` SKU-паспорта (напр. `["metacognition", "decision-making"]`), перевіряються на відсутність дублікатів та заборонених слів (K5).  
   - **Price:** Встановлюється як значення з `price_anchor` (K2), напр. `"199 USD"`. Якщо є діапазон (`"79/199 USD"`), береться верхня межа.  
   - **Description:**  
     - Обов’язкові пункти:  
       - Формат: `"Формат: {format}"` (з K2).  
       - Ліцензія: `"Ліцензія: {EULA з K3}"`.  
       - Посилання на демо-версію (якщо є, з K3).  
     - Заборонено (з K5):  
       - Непідтверджені claims ("підвищує продуктивність на 200%").  
       - Неузгоджені терміни (напр., "файл" замість "шаблон").  
     - Перевірка вмісту: Назва шаблону в description має збігатися з `title` SKU, а опис функцій — з реальним вмістом Notion-сторінки (K3).  

2. **Хід міркування:**  
   - **Title/Tags:** Уніфіковані на основі K2, щоб уникнути розбіжностей між виконавцями.  
   - **Price:** Фіксується за правилом якоря з K2 (не довільно).  
   - **Description:** Контрольований шаблон з обмеженнями K5 (юридичні ворота) та перехресною звіркою з K3.  
   - **Звірка claims:** Перед публікацією Notion-сторінка товару перевіряється на відповідність опису (напр., якщо вказано "база даних для відстеження рішень", вона має бути в шаблоні).  

3. **Емпірична перевірка:**  
   - Взяти реальний SKU-паспорт (напр. з K2):  
     ```json
     {
       "title": "Decision Journal Notion Template",
       "tags": ["metacognition", "decision-making"],
       "price_anchor": "premium: 199 USD"
     }
     ```  
   - Згенерувати лістинг за правилами:  
     - **Title:** `"Decision Journal — Notion Template"`.  
     - **Price:** `199 USD`.  
     - **Description:** Перевірити наявність демо-версії та відсутність заборонених слів.  
   - Запустити перевірку збігу `title`/опису з вмістом Notion-сторінки:  
     ```bash
     curl -s "https://api.notion.com/v1/pages/ПОСИЛАННЯ_СТОРІНКИ" | jq '.properties.description.rich_text[].plain_text'
     ```  

4. **Ризики:**  
   - Якщо `price_anchor` містить нечислове значення (напр. "premium"), K4 не зможе автоматично вивести ціну.  
   - Не всі теги з SKU можуть підходити для платформи (напр., Etsy має обмеження на довжину тегів).  

5. **Сценарії збою:**  
   - Відсутність демо-версії в Notion-шаблоні (порушує заявку в description).  
   - Розбіжність між `title` SKU і назвою сторінки в Notion.  

**Приклад лістингу:**  
```markdown
**Title:** Decision Journal — Notion Template  
**Tags:** metacognition, decision-making  
**Price:** 199 USD  
**Description:**  
Формат: Notion Template. Ліцензія: Personal use only, no resale.  
Демо: [Посилання на шаблон]. Включає базу даних для відстеження рішень та інтеграцію з Google Calendar.  
```  

**Обмеження:**  
- У мене немає доступу до Notion API для автоматизації звірки claims. Мінімальний стенд — ручна перевірка в GUI.  
- Якщо `price_anchor` не структурований (напр. "від $99"), правило для ціни потребує доопрацювання.  

**Використані джерела:**  
- SKU-паспорт K2.  
- Вимоги K5 (юридичні обмеження).
