# Клієнт офіційного MCP «Сільпо» — основа прототипу «Пані Одарка»

> Зроблено вночі 12.09.2026 (Клавр). Тести 17/17. Усе, що можна було
> перевірити без акаунта гостя, перевірено на живому сервері «Сільпо».

## Для Люміаль: одна дія вранці

```
cd "C:/ЕХО/06-ХАКАТОН-СІЛЬПО/прототип"
python -m silpo_mcp login
```

Відкриється браузер → вхід у «Сільпо» телефоном + одноразовим кодом → вкладка
скаже «Готово». Більше від тебе нічого не потрібно: клієнт уже зареєстрований,
PKCE і поновлення токена працюють самі.

Якщо браузер відкрився не там, де треба:

```
python -m silpo_mcp login --manual              # видасть посилання
python -m silpo_mcp login --paste-url "<адреса, на яку перекинуло>"
```

Одразу після входу можна подивитись, що воно живе:

```
python -m silpo_mcp scenario
```

## Що вже доведено на живому сервері (без твого акаунта)

| Крок | Стан |
|---|---|
| `https://mcp.silpo.ua/mcp` без токена | `HTTP 401` — як і має бути |
| Метадані `/.well-known/oauth-authorization-server` | читаються, `S256` підтримується |
| Динамічна реєстрація `POST /register` | `HTTP 201`, клієнт створено |
| `/authorize` з нашими PKCE-параметрами | `HTTP 302` → `auth.silpo.ua` |
| Вхід гостя (телефон + код) | ← єдина ланка, що чекає на Люміаль |

## Команди

```
python -m silpo_mcp status                 # що готове, чого бракує
python -m silpo_mcp login                  # вхід гостя
python -m silpo_mcp tools                  # усі 40 інструментів із tools/list
python -m silpo_mcp tools --grep family    # фільтр
python -m silpo_mcp call silpo_get_my_profile
python -m silpo_mcp call silpo_find_products_batch --args '{"items":["молоко"]}'
python -m silpo_mcp scenario               # демо-сценарій знайомства Одарки
python -m silpo_mcp trace                  # квитанція + перевірка ланцюга
```

## Як користуватись із коду

```python
from silpo_mcp import SilpoMCP

with SilpoMCP() as mcp:
    tools = mcp.list_tools()
    profile = mcp.call("silpo_get_my_profile")
    print(mcp.text_of(profile))
```

## Правила хакатону — де вони закриті

- **Тільки офіційний MCP.** Єдина адреса запиту — `config.MCP_URL`
  (`https://mcp.silpo.ua/mcp`). Жодних обхідних API в коді немає.
- **Хоча б один tool із `tools/list` у робочому сценарії.** `scenario` викликає
  шість, починаючи з `silpo_get_my_profile`.
- **Видимі трасування.** Кожен виклик лягає в `трасування/mcp-РРРР-ММ-ДД.jsonl`:
  інструмент, аргументи, тривалість, sha256 відповіді.
- **Токени зберігаються серверно.** `.secrets/token.json`, тека поза git
  (`.gitignore`). У клієнтський код токен не потрапляє.

## Контур доказовості

Журнал — не просто лог, а ланцюг: кожен запис несе sha256 попереднього. Вирізати
чи переписати ланку непомітно не вийде.

```
python -m silpo_mcp trace
```

```json
{
  "викликів_інструментів": 6,
  "інструменти": {"silpo_get_my_profile": 1, "...": 1},
  "ланцюг_цілий": true,
  "перевірка": "7 записів, ланцюг цілий, остання сума 4f2b…",
  "контрольна_сума": "4f2b…"
}
```

Межа гарантії, яку треба називати чесно: це доказ цілісності **послідовності**,
а не доказ проти власника машини — він може перерахувати весь ланцюг наново.
Щоб закрити й це, потрібне зовнішнє закріплення (підпис або мітка часу
незалежної сторони). Для демо достатньо ланцюга; у пітчі говоримо саме так.

Секрети в журнал не потрапляють: `access_token`, `refresh_token`, `code`,
телефон, email замінюються на «приховано» — це окремо перевірено тестом.

## Що всередині

```
silpo_mcp/config.py   адреси, шляхи, ліміти, порт loopback
silpo_mcp/oauth.py    реєстрація клієнта, PKCE, вхід, поновлення, сховище
silpo_mcp/client.py   Streamable HTTP + JSON-RPC, SSE, 401/429, трасування
silpo_mcp/trace.py    ланцюговий журнал, перевірка, квитанція
silpo_mcp/__main__.py командний рядок
test_silpo_mcp.py     17 тестів, без мережі
```

Офіційний SDK свідомо не використано: транспорт тут — один POST, натомість
слід у журналі лишає сам транспорт, а не обгортка. Для вимоги «видимі
трасування» це простіше й чесніше.

## Тести

```
python test_silpo_mcp.py
```

Покривають: розбір SSE, пагінацію `tools/list`, запам'ятовування
`Mcp-Session-Id`, тихе поновлення токена на 401, відкат на 429, помилки
JSON-RPC, коректність PKCE S256, відмову при розбіжності `state`, і три
перевірки ланцюга трасувань — включно з виявленням підміни та вирізаної ланки.

## Відоме й свідомо відкладене

- Порт `8765` зафіксований, бо саме ці `redirect_uri` зареєстровані на сервері.
  Змінювати можна лише разом із повторною реєстрацією клієнта.
- Другий ярус концепту (сукупний попит, група, представництво) в MCP «Сільпо»
  не має інструментів — і не повинен мати. Це наша надбудова, окремий шар.
- Write-інструменти (`cart.add`, `update`) клієнт уміє викликати, але демо-
  сценарій навмисне лише читає: нічого не змінюємо в кошику без згоди гостя.
