# EXO Scan — каркас діагноста

**Що це:** технічна основа для побудови EXO Scan — інструмента діагностики
спроможності підприємства. Тут лежить структура, не методологія.

## Що тут є

| Файл | Що робить |
|------|-----------|
| `questions_schema.json` | Правила структури для файлу питань. Визначає які типи питань бувають, як працює розгалуження, як записуються ваги. |
| `scoring_engine.py` | Рушій оцінки. Бере питання + відповіді → видає бали по вісях, рівень D0-D4 і рекомендації. Без штучного інтелекту — все прозоро і відтворювано. |
| `test_scoring.py` | 8 тестів що перевіряють правила з брифу (D0-D1 блокує повний EXO, детермінованість, брак даних = чесне ⚪). |

## Чого тут НЕМАЄ (і чому)

**Питань і ваг.** Це ваша методологія — Люміаль і Аетрема. Каркас готовий
їх прийняти: заповніть файл `questions.json` за структурою зі схеми,
а рушій порахує все автоматично.

## Як це працює простими словами

1. Ви пишете питання у файл `questions.json`:
   - текст питання українською
   - варіанти відповідей
   - яка відповідь на яку вісь впливає і наскільки
   - за якої умови показувати питання (розгалуження)

2. Користувач відповідає на сайті (10-15 хвилин).

3. Рушій рахує:
   - **8 осей радару** (бали 0-4, або ⚪ якщо мало відповідей)
   - **Рівень цифрового субстрату** (D0-D4)
   - **Теги рекомендацій** (наприклад: «спочатку потрібна базова цифровізація»)

4. Результат показується на екрані одразу.

## Типи питань

- **single_choice** — один варіант з кількох (найчастіший)
- **multi_choice** — кілька варіантів (напр. «які системи використовуєте»)
- **scale** — числова шкала
- **number** — точне число (напр. «скільки людей у відділі»)
- **text** — відкрита відповідь (мінімум таких — для безпеки)

## Правила з брифу, вшиті в рушій

1. **D0-D1 → спочатку базова цифровізація.** Якщо підприємство на рівні
   «папір» або «скани» — рушій автоматично додає тег
   `DIGITAL_FOUNDATION_REQUIRED`. Повний EXO тут передчасний, але шлях
   до нього починається саме тут (дорожня карта, не відмова).

2. **Однакові відповіді = однаковий результат.** Завжди. Це не ШІ-фантазія,
   а прозорий розрахунок.

3. **Недостатньо відповідей на вісь → ⚪.** Чесне «не знаємо» замість
   вигаданого балу. Радар з двома ⚪ викликає більше довіри, ніж вісім
   намальованих цифр.

4. **Версія методики в кожному результаті.** Щоб повторний скан через
   3 місяці був порівнянним.

5. **Часткове проходження зберігається.** Хто пішов на 6-му екрані з 9 —
   теж сигнал.
